Phase 10 · months 9–10

AI security and safe autonomy

Outcome

Design agent systems – including the coding agents your engineers run – under the assumption that model output, retrieved content, tool responses and generated code may all be malicious, misleading or compromised.

Threat model the whole loop

Direct and indirect prompt injection, tool poisoning, retrieval poisoning, data exfiltration, confused-deputy attacks, credential leakage, privilege escalation, cross-tenant leakage and sandbox escape. Identify which inputs are untrusted and what an attacker would want. Any product that ingests content it does not control – web pages, emails, uploaded documents, tickets – faces indirect injection as a real, not theoretical, risk.

Least privilege by architecture

No broad ambient credentials for the model. Tools execute under narrowly scoped identities; read is separated from write; credentials are short-lived; sensitive actions require policy checks and often human approval.

Coding-agent security

Coding agents run with a developer's privileges on a developer's machine. Learn permission modes and allow/deny rules, sandboxed execution, keeping secrets out of agent context, and supply-chain risks such as agents installing hallucinated or typo-squatted packages. Note which of your Phase 1 tools do and do not sandbox – a multiplexer organises agents; it does not contain them.

Sandbox execution

If agents execute code or shell commands, isolate them: container boundaries, filesystem scoping, network egress controls, CPU/memory/time limits and disposable environments. Generated code is untrusted code.

Learn the managed sandbox services built for exactly this – E2B, Modal, Daytona, Vercel Sandbox and Cloudflare's sandboxes – and compare them on isolation model (microVM versus container), cold-start time, session length, egress control and cost. Then build the same thing yourself once with Firecracker-style microVMs or gVisor containers on AWS so you understand what you are buying.

Case study: the LiteLLM supply-chain compromise

On 24 March 2026 two LiteLLM releases on PyPI shipped malicious code that harvested environment variables, SSH keys and cloud credentials; they were live for roughly 40 minutes after a maintainer token was compromised. An LLM gateway is, by design, the component holding every provider key, which makes it an ideal target. Write a short postmortem-style analysis: what dependency pinning, hash verification, egress controls and credential scoping would have limited the blast radius in your own stack – and which of your agents install packages unsupervised.

Context and data safety

Label external content, separate instructions from data, and do not rely on prompting alone to stop exfiltration. Enforce access control before retrieval and before tool execution, and make policy denials visible in traces.

Build: adversarial test suite

Malicious documents, web pages, PR comments and tool responses that try to override instructions, request secrets or trigger privileged tools; cross-tenant access tests; malformed arguments. Run it on every significant agent change.

Exit milestone

You can present a threat model for your agent platform, show the control for each major risk and demonstrate that a prompt injection cannot grant capabilities the caller did not already have.
