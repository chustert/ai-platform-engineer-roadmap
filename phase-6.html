Phase 6 · Months 5 to 7

Run agent workloads on AWS

Outcome

You know AWS well enough that an AI service is one more workload you can deploy securely, cheaply, and the same way every time.

Why cloud basics matter here

AI platform projects often fail on cloud basics: IAM policies that allow too much, NAT gateway costs nobody noticed, retries that make an outage worse, Lambda concurrency without a limit, and no separation between the control plane and the workload. Agents will write infrastructure code for you. They will not warn you that a policy allows too much unless you know to ask.

Compute

Learn Lambda in depth: concurrency, cold starts, SnapStart, packaging, and failure destinations. Learn ECS on Fargate for container workers, and enough EC2 to understand what runs underneath. Know when serverless fits and when a pool of long-running workers is cheaper or simpler.

Messaging and workflows

Learn SQS, SNS, EventBridge, and Step Functions. Learn visibility timeouts, dead-letter queues, retry behaviour, ordering, deduplication, and at-least-once delivery. Each of these maps directly to a way of running agents reliably.

Storage, networking, and identity

Learn when to use S3, DynamoDB, RDS for Postgres, and ElastiCache. Learn VPCs, subnets, security groups, NAT, private endpoints, and load balancers. Learn IAM, STS, KMS, and Secrets Manager in depth. You should be able to explain exactly which principal can do what, and why.

Bedrock and managed agent services

Learn how to call models through Bedrock and how its provider abstraction works. Learn the managed agent services AWS offers, such as Bedrock AgentCore. Keep your own agent interfaces portable, so that you can use managed services without tying every part of the architecture to them.

Build an event-driven agent runner

Take agent jobs from an API through a durable queue. Workers lease jobs, save state, emit traces, and send jobs that keep failing to a dead-letter queue. Deploy with Terraform or CDK, keep environments separate, give each role the least privilege it needs, and estimate what the infrastructure costs. Review every IAM policy that the agent writes yourself.

You are done when

You can draw an AWS architecture for an agent platform on a whiteboard, explain its network and IAM boundaries, predict how it fails, and deploy it from code without using the console.
