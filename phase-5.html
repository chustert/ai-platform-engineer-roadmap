Phase 05 · months 4–6

Agent architecture and orchestration

Outcome

Use agents only where reasoning is valuable, surround them with deterministic workflow control, and design long-running tasks as explicit state machines.

Patterns before frameworks

Master the patterns: single-agent loop, router, supervisor and workers, planner/executor, evaluator/optimizer, map/reduce and human-in-the-loop. Learn what state each needs, how it terminates and how it recovers. Framework APIs will change; these patterns will not. You have already met the supervisor pattern by hand in Phase 1 – running and watching parallel coding agents.

Deterministic shell, probabilistic core

Push deterministic concerns out of the model. State transitions, budgets, permissions, retries, persistence and approvals belong in code. Use the model for interpretation, planning, synthesis and judgment where deterministic code would be brittle.

Durable state and durable execution

Persist workflow state after meaningful steps so a long-running agent survives restarts. Design steps to be replayable and tools idempotent where possible. Store enough provenance to reconstruct what the agent saw and why it acted.

Then learn the tools that do this for you. Durable execution engines turn the agent loop into workflow code where every model call and tool call is journalled, so a run can crash, wait hours for an approval or back off from rate limits and resume exactly where it left off. Temporal is the mature standard and is reported to run agent workloads at OpenAI (Codex), Replit and Cursor. Lighter options: DBOS (durability on your existing Postgres, no new infrastructure), Inngest (managed, fits serverless TypeScript stacks on Vercel or Cloudflare) and Restate (a single lightweight server). AWS Step Functions is the AWS-native equivalent. Learn Temporal properly and one lighter option that fits your product's stack.

Framework practice

Now learn the Claude Agent SDK (purpose-built for coding and file-manipulating agents – the internal SDLC-tooling use case) and LangGraph (checkpointed, graph-shaped workflows). Rebuild one workflow you previously had built from scratch and compare the operational trade-offs; often the bare model SDK plus a durable execution engine is the simplest answer. Also run a coding agent headless inside CI – the same harness you use interactively, now as a workload.

Two situational additions: the Vercel AI SDK if your product or day-to-day work is TypeScript, and Microsoft Agent Framework (the AutoGen successor, with C# and Python parity) before interviewing at .NET shops. Pydantic AI is a good lighter-weight typed option in Python. Skip framework tourism beyond that.

Build: PR review system

On every pull request: classify changed systems; retrieve relevant architecture and standards; run specialised reviewers for security, data, architecture and tests; aggregate and deduplicate findings; run a confidence pass; post only findings above a threshold. Add hard limits for turns, time and token spend. Point it at your own repositories first – it will be reviewing agent-written code, which is exactly the job.

Exit milestone

You can draw the state machine for an agent workflow, identify deterministic versus model-driven transitions, recover an interrupted run and explain why multi-agent design is or is not justified for a task.
