The final test

Could another strong engineer inspect your system and trust it to take real actions? Could they understand its cost, permissions, failure modes, and quality without your explanation? Could you get a team to change how it works because your way is better? If the answer to all three is yes, you work like an AI platform engineer.

Priority order

If you have to cut, keep this order:

  1. Working with coding agents and reading their code.
  2. Model cost.
  3. Retrieval and context.
  4. MCP tool servers.
  5. Agent workflows as state machines.
  6. AWS.
  7. OpenTelemetry tracing.
  8. Evaluations.
  9. Reliability.
  10. Security.
  11. The internal platform.
  12. Developer experience and adoption.
  13. The Forge capstone.
  14. Kubernetes, only if you need it.

Which languages to read

Read Python and TypeScript fluently from the start. Learn to read C# before you apply to .NET companies. When agents write the code, a new language costs you mainly the time to learn its idioms, runtime behaviour, and failure modes. Those are exactly the things to study.
