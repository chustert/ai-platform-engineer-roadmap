Phase 09 · months 8–10

AI SRE and reliability

Outcome

Operate agents as distributed production workloads with SLOs, bounded failure, graceful degradation and practised incident response.

Define reliability in user terms

An agent can return HTTP 200 and still fail the task. Define SLIs around useful completion, quality, latency and cost – for example, successful answers with valid citations, severe false-positive rate, p95 latency and cost per answer.

Failure engineering

Circuit breakers, bounded retries with jittered backoff, concurrency limits, load shedding, DLQs, poison-message handling, idempotency and replay. Model partial failure explicitly: the model succeeds but the tool fails; the tool succeeds but the response is lost; the worker dies after creating a branch but before recording completion.

Budgets and runaway control

Hard limits on elapsed time, model calls, tool calls, tokens, dollars and recursion depth for every run; per-tenant quotas and a global kill switch. A reliable agent fails closed or degrades to a known mode rather than looping forever.

Degraded modes and provider failure

Design a provider-outage strategy per workflow: route to another model, queue and wait, or fall back to a reduced deterministic result – and document the semantic difference rather than silently swapping in a weaker system.

Build: game days

Inject model timeouts, 429s, malformed output, duplicate deliveries, tool outages, database latency, expired credentials and budget exhaustion into your product's staging environment and the agent runner. Verify alerts, runbooks and recovery, and write a postmortem for at least one induced incident.

Exit milestone

You can define an SLO, explain its error budget, run a failure drill, recover safely and show that the platform cannot spend or loop without bound.
