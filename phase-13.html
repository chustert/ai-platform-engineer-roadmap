Phase 13 · months 9–12

Capstone: Forge – an internal AI engineering platform

Outcome

Integrate the roadmap into one credible system with real users that demonstrates Staff-level platform thinking rather than a collection of disconnected demos.

The capstone brief

Forge is an internal platform for AI-assisted software delivery. It supports a handful of useful engineering agents while centralising the hard production concerns: context, tools, identity, budgets, observability, evaluations, approvals and reliability. Its first users are you (on your product and other work) and, ideally, a small team.

Suggested agents

Start with a PR review agent, dependency-upgrade agent, documentation agent and incident-investigation assistant. Add a security agent only once permissions and evaluation are mature. Each reuses the same platform interfaces for models, tools, context, tracing and policy.

Reference architecture

A CLI/SDK and optional GitHub App; an agent gateway/control plane feeding a durable runtime; explicit context-retrieval, MCP/tool and state components; centralised model-provider access; OpenTelemetry traces into your observability stack; experiments and evals in an LLM evaluation system; a shared coding-agent configuration; IaC deployment.

Operational requirements

Every run has a hard budget and timeout. Every side effect is authorised. High-risk actions require approval. Every workflow version is identifiable. Traces connect model calls, retrieval and tools. Production failures become eval cases. Queue-driven jobs are replayable. Secrets never enter prompts. Teams have quotas and audit logs.

Staff-level artifacts

An RFC for the platform architecture, an ADR for orchestration choice, a threat model, an SLO document, an incident runbook, a model/provider strategy, an eval methodology, a coding-agent rollout plan and a cost report; an architecture diagram and a short recorded demo.

Success criterion

A reviewer browsing the repository concludes: this person understands how agentic workloads behave in production, knows how to constrain non-determinism, makes sound cloud, reliability, security and developer-experience trade-offs, and communicates those decisions clearly – and the thing is actually used.

Exit milestone

Forge is in daily use by at least one real user besides the demo, integrates the earlier phases, and every claim in your CV about it is backed by an artifact in the repository.
