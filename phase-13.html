Phase 13 · Months 9 to 12

Build Forge, the capstone platform

Outcome

You combine the phases into one system with real users that shows Staff-level platform thinking, instead of a set of unconnected demos.

What Forge is

Forge is an internal platform for software delivery with AI agents. It runs a small number of useful engineering agents and handles the hard production concerns for all of them in one place: context, tools, identity, budgets, tracing, evaluations, approvals, and reliability. Its first users are you, on your product and your other work, and ideally a small team.

Start with four agents

Start with a PR review agent, a dependency-upgrade agent, a documentation agent, and an assistant for incident investigation. Add a security agent only after your permissions and evals are mature. Every agent uses the same platform interfaces for models, tools, context, tracing, and policy.

Use this reference architecture

Forge has these parts:

  • A CLI and SDK, and optionally a GitHub App.
  • An agent gateway and control plane that send work to a durable runtime.
  • Separate components for context retrieval, MCP tool servers, and stored state.
  • One place that all model provider calls go through.
  • OpenTelemetry traces sent to your tracing tools, and experiments and evals recorded in an eval system.
  • A shared coding-agent setup.
  • Deployment through infrastructure as code.

Meet these operating requirements

Every run has a hard budget and a timeout. Forge authorises every side effect. High-risk actions need approval. You can identify every workflow version. Traces connect model calls, retrieval, and tools. Production failures become eval cases. You can replay jobs from the queue. Secrets never appear in prompts. Every team has quotas and audit logs.

Write the Staff-level documents

Write an RFC for the platform architecture and a decision record for your choice of workflow engine. Write a threat model, an SLO document, an incident runbook, a model provider strategy, an eval method, a rollout plan for coding agents, and a cost report. Draw an architecture diagram and record a short demo.

Check it against this test

A reviewer who reads the repository should conclude four things. You understand how agent workloads behave in production. You know how to limit what varies between runs. You make sound trade-offs in cloud, reliability, security, and developer experience. You explain those decisions clearly. The platform should also be in real use.

You are done when

At least one real user besides you uses Forge every day, it brings the earlier phases together, and every claim about it on your CV links to an artifact in the repository.
