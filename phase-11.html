Phase 11 · Months 10 to 12

Build an internal AI platform

Outcome

You turn individual agents into a platform that makes it easier for every team to build safe, observable agents and to work with coding agents.

Run the platform like a product

A platform has users, workflows, onboarding problems, reliability expectations, and a roadmap. Interview developers and find the problems they keep hitting: model integration, tracing, tools, budgets, evaluation, prompt deployment, approvals, identity, context, and getting consistent results from coding agents. Build the smallest shared solution that removes a real problem.

Build both halves of the platform

An internal AI platform has two halves. The agent runtime runs the agents your organisation ships. It holds agent definitions, versions, policies, budgets, eval settings, and telemetry. The coding-agent setup makes every engineer's coding agents safer and more useful, with shared skills, context-file templates, hooks, MCP servers, permission policies, and telemetry. The Staff role is mostly the second half, and most roadmaps cover only the first.

Offer small, safe building blocks

Offer small APIs such as create_agent, register_tool, run_eval_suite, require_approval, set_budget, and trace_workflow. Provide templates for common patterns instead of one framework with endless options. Make the defaults safe: retries have limits, tracing is on, every run needs a budget, and privileged tools need a policy.

Support many teams

Separate teams and tenants. Add quotas, audit logs, feature flags, staged rollouts, and version compatibility. Keep migrations routine. A platform that breaks every team that uses it slows the organisation down.

Build the first slice of Forge

Put the PR reviewer, the context engine, and the tool servers behind one developer interface. Include an SDK and CLI, a documented local environment, an example agent, standard tracing, the model gateway, and an eval hook. Add your shared agent setup from Phase 1: skills, hooks, and MCP settings. Then build a second agent using only the public interfaces, to find parts that depend on internals by accident.

You are done when

Another engineer can create and run a small agent on your platform, and get a well-configured coding-agent setup from it, without knowing its internals. You still see spend, reliability, and policy for every agent in one place.
