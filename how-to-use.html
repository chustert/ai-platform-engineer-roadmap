How to use this roadmap

This roadmap is a curriculum for becoming an AI platform engineer. Each phase gives you something to learn, something to build, and a checklist that tells you when you are done. At the end of every phase you should have work another engineer can inspect: running software, traces, evals, dashboards, runbooks, and written design decisions.

The roadmap assumes that coding agents write most of the code. You decide what to build, write the spec, check what the agent produces, and run the result in production. Typing code by hand is no longer the slow part of the job. Knowing what is correct and safe is.

The order of the phases matters

Phase 1 teaches you to work with coding agents, because you use them to build everything after it. The next phases cover model cost, retrieval, tool servers, agent workflows, AWS, tracing, evaluations, reliability, and security. Only after those do you build a platform for other teams. If you learn a framework before you understand the problem it solves, you cannot tell when the framework hides a bug.

Plan for about 9 hours a week

The plan takes about 12 months at 8 to 10 hours a week outside work. Agents do most of the typing, so the build work goes faster than it did a few years ago. Learning to operate what you build is what takes the time. If your day job covers the same ground, count those hours.

The phases overlap on purpose. For example, you add tracing in Phase 1, although tracing gets its own phase later.

Count only evidence

For each skill, ask what artifact proves you have it. A certificate proves little. A deployed service with a cost dashboard, a regression suite, failure tests, and a written design decision proves a lot. A product that real people use proves the most. For that reason the roadmap puts as much work as possible into a real product. The page "Do the work on a real product" explains how to pick one.

The goal

Become the engineer other teams trust to make autonomous software reliable, cheap to run, observable, and safe. That includes the coding agents those teams use every day.

Four stages from builder to Staff engineer

You move through four stages. Each stage adds to the one before it.

  1. Builder. You ship useful AI products in days instead of weeks by directing coding agents well.
  2. Operator. You run those products in production and find the cause of failures from evidence.
  3. Platform engineer. You turn what you built into something other teams can reuse.
  4. Staff engineer. You set technical direction, write standards, and get teams to adopt them without formal authority.
