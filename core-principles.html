Core principles

Code is cheap; verification is expensive.

When agents can produce a feature in minutes, the scarce resource is knowing whether it is correct, safe and worth shipping. Invest in the harness – tests, types, evals, traces, review – more than in the generation.

Own what you merge.

Authorship no longer implies understanding, so accountability has to be explicit. If you cannot explain why a change is safe, it is not ready, whoever wrote it.

Frameworks are replaceable; systems knowledge is durable.

Learn what a router, durable workflow, retry policy and evaluation loop are before relying on a library implementation. The same applies to agent tooling: the multiplexer or IDE you use this quarter will change; the supervision pattern will not.

Non-determinism must be engineered around.

The model can vary. Your permissions, budgets, persistence, auditability and failure boundaries should not.

Every production failure should make the system stronger.

Capture failures as traces, convert representative cases into evals, fix the system, and prevent recurrence in CI.

Autonomy is a permission problem as much as an intelligence problem.

A model – including your own coding agent – should only be able to take actions that the surrounding system explicitly allows.

Cost is a reliability dimension.

A workflow that succeeds but burns unpredictable token and tool budgets is not production-ready.

The best platform disappears into the workflow.

Do not force teams to learn your platform. Make the safe path the easiest path.
