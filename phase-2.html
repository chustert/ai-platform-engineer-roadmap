Phase 02 · months 1–3

LLM systems and model economics

Outcome

Understand what the model is doing well enough to make architecture, latency, quality and cost decisions instead of treating the LLM as a magical API.

Mental model

Learn the practical mechanics behind tokens, tokenizers, embeddings, transformers, attention, context windows, KV caches, sampling, structured output, multimodality and inference. You should understand why long context is expensive, why repeated prefixes can be cached and why latency grows with output length.

Learn where model behaviour ends and application behaviour begins. The model predicts output; your system decides what context it sees, which tools exist, whether its arguments are valid, what permissions apply, when to retry, when to stop and what counts as success.

Model selection and routing

Separate cheap classification/routing tasks from expensive reasoning tasks. Experiment with an escalation policy where a smaller model tries first and a stronger one is used only when validation fails. Measure quality and cost rather than assuming the largest model should do everything. Apply the same thinking to your own coding agents.

Economics as architecture

Create a cost model for every run: input, output and cached tokens, embeddings, reranking, tool/API cost, retries and failed runs. Add per-task and per-user budgets. Track p50 and p95 cost, not only averages, because pathological runs matter. Experiment with prompt caching, context compression, retrieval instead of stuffing, parallel calls and output constraints. The objective is not minimum tokens; it is maximum useful task success per dollar and per second.

Build: model router, in production

Extend the Phase 1 service into a provider-agnostic model gateway with at least two profiles (low-cost/fast and high-capability), routed by deterministic rules. Then apply the same cost model and routing to your product, where the numbers are real. A before/after cost-per-answer chart at unchanged quality is one of the strongest artifacts you can produce.

Build versus buy: model gateways

Compare your router with off-the-shelf gateways: LiteLLM (self-hosted, broad provider support), Portkey (managed, strong dashboards and guardrails) and Bedrock's gateway options (traffic stays inside AWS). Write a one-page ADR on which you would adopt for your product and which for an AWS-standardised company.

Exit milestone

Given a workload, you can estimate its cost, identify the dominant cost and latency drivers, choose a model tier and design a fallback. You can explain why a large context window does not mean every request should fill it – and you can show it on your product's own numbers.
