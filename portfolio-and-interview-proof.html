Beyond the phases

Portfolio and interview proof

A hiring manager should not have to infer your experience from buzzwords. Structure your product case studies and the Forge repository so each claim is backed by an artifact.

Repository structure

A strong Forge repository might include /platform, /agents, /tools, /context, /evals, /infra, /observability, /agent-config (skills, hooks, MCP settings), /docs/rfcs, /docs/adrs, /runbooks and /security, with a top-level architecture diagram and a ten-minute quick-start.

Case studies to write

  • How the product cut cost per task while holding measured quality.
  • How a real production failure became a regression eval.
  • How I run several coding agents in parallel without losing control or quality.
  • Rolling out a shared coding-agent setup to a team: what worked, what did not, adoption numbers.
  • Why write tools require approval and how the policy layer works.
  • How retrieval is evaluated separately from answer quality.
  • How workflow state survives worker restarts and duplicate delivery.
  • How tracing shortened diagnosis of a multi-step agent failure.

System-design topics to rehearse

  • Roll out Claude Code and internal MCP servers to 300 engineers: permissions, telemetry, cost governance, enablement.
  • Design an internal coding-agent platform used by 500 engineers.
  • Design a multi-tenant agent execution service with per-team budgets.
  • Design a PR reviewer that keeps severe false positives below a threshold.
  • Design secure tools that let agents deploy to staging but not production.
  • Design a context service over repositories, tickets and documents with ACLs.
  • Design observability and incident response for a non-deterministic workflow.

What to say less often

Avoid leading with framework or tool names. Lead with constraints and outcomes: "we used a durable state machine because jobs run for 20 minutes and workers are disposable" beats "I used LangGraph"; "I run four isolated agents and gate merges on evals" beats "I use Herdr". Show that the tool followed from the problem.
