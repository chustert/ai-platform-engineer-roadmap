Beyond the phases

Weekly operating rhythm

The fastest route to expertise is a tight build-measure-learn loop. Avoid spending a month on courses before touching the system; each week should produce a visible improvement in capability or reliability.

Session 1: choose one capability

Define one narrow result – "add trace propagation through SQS", "measure retrieval recall at 5", "require approval before write tools" – and write the expected behaviour and acceptance tests as a short spec before any agent starts.

Build sessions

Run agents aggressively and in parallel, each in its own worktree, with your spec and context files doing the steering. Ask for options and trade-offs before implementation on anything architectural. Then verify: tests first, risk-weighted reading of the diff second, running it third. The scarce skill you are training is deciding what is safe and appropriate to merge.

Reliability session

One session a week adds no features. Break the system, inspect traces, improve tests and evals, add a missing metric, simplify a boundary or reduce cost. This is how you avoid an impressive demo with production-grade fragility.

Final session: produce evidence

Update the README or architecture diagram, add a short ADR, capture before/after metrics, record any failure worth turning into an eval, and fold anything you had to tell an agent twice into a context file or skill.
