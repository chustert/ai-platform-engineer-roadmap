The target profile

The end-state is a hybrid engineer: part backend engineer, part distributed-systems engineer, part SRE, part security engineer, part developer-experience engineer and part AI specialist – who works primarily by directing agents. The model itself is only one dependency inside the system.

CapabilityWhat excellent looks likeProof you can show
AI-native developmentRuns several coding agents in parallel with isolation, specs and review gates; configures agent tooling (context files, skills, hooks, MCP, permissions) for a team.A documented agent workflow that other engineers adopt; measured throughput and defect rates.
Code literacyReads Python and TypeScript (and C# where needed) fluently; spots concurrency, error-handling, security and test gaps in agent-written diffs.Review notes on real PRs; seeded-bug hit rate; clean incident debugging.
Distributed systemsDesigns retries, queues, idempotency, backpressure, state and failure recovery.Agent workflows that survive partial failure and can be replayed safely.
Cloud/platformUnderstands AWS compute, messaging, storage, IAM, networking and IaC.Reproducible environments deployed through Terraform/CDK and CI/CD.
LLM systemsUnderstands model behaviour, context, tools, RAG and inference economics.Model-routing and context strategies justified by measured outcomes.
Agent orchestrationUses state machines, routers, supervisors and human approval appropriately.Durable multi-step workflows, not brittle prompt chains.
Reliability and evalsDefines SLOs, traces behaviour and detects regressions before release.Eval suites, dashboards, alerts and incident playbooks.
SecurityTreats model output, retrieved content and agent-written code as untrusted input.Least-privilege tools, sandboxing, approvals and audit logs.
Product judgmentDecides what to build and when output is good enough to put in front of users; works directly with customers.A product with real users, usage metrics and a visible feedback loop.
Developer platformCreates paved roads – for humans and their agents – that teams choose because they reduce friction.SDKs, templates, shared skills/MCP servers, docs and adoption metrics.
Staff leadershipMakes architecture calls, writes RFCs and influences across team boundaries.Accepted standards, design reviews, mentoring and incident leadership.
