Phase 12 · months 10–12

Developer experience, paved roads and adoption

Outcome

Make the correct engineering path the fastest path – for humans and their agents – and get teams to choose it.

Developer empathy is technical leverage

Internal platforms fail when they optimise for the platform team instead of the developer. Measure setup time, local feedback time, CI wait time and manual steps. Pair with users and watch where they hesitate. Treat every confusing step as a product defect.

Agent experience is developer experience

Agents iterate on whatever feedback loops you give them, many times per task. A slow test suite that costs a human a few minutes a day costs an agent-heavy team hours. Fast deterministic tests, clear error messages, reproducible local environments and accurate context files are now the highest-leverage DevEx investments.

Local development

A one-command local environment with containers and service emulation. Seed realistic but safe data. Make model calls mockable or recordable so neither developers nor agents burn tokens on every unit test – for AI platforms this matters more than any single emulator.

Aspire (formerly .NET Aspire, renamed with version 13 in November 2025) is worth a weekend even outside .NET: it now treats Python and JavaScript as first-class, orchestrates a multi-service app locally with built-in telemetry, and ships an MCP server that lets Claude Code query running resources, logs and traces. That is a concrete example of an agent-ready dev environment. Its deployment tooling leans towards Azure, so treat it as a local-dev tool.

LocalStack emulates AWS services locally and appears in platform-role job postings, so learn it before applying to AWS-heavy teams that use it – but it is no longer open source. Since March 2026 the Community edition has been folded into a single image that requires an account and auth token, the free tier excludes CI credits, and paid plans start around US$39 a month. Learn the pattern (local cloud emulation) rather than betting on the product; Moto covers many AWS mocks inside tests.

CI/CD and previewability

Separate unit tests, integration tests, targeted evals and full eval suites. Create preview environments for meaningful agent changes. Use feature flags and canary rollout for prompts and workflows, not only code. Tune build and CI performance; it compounds.

Driving adoption without mandates

Run pairing sessions and office hours; demo real wins; publish before/after numbers; collect and act on complaints; give teams an escape hatch. Measure adoption honestly (active users, retained users, tasks completed) rather than installs.

Build: onboarding and adoption test

Ask a colleague to build a small agent from your docs without help, and separately to adopt your coding-agent setup for a week. Observe every problem. Target: create project, run locally, add a tool, run an eval, inspect a trace and deploy to test with minimal bespoke setup.

Exit milestone

You can show quantitatively that the platform reduces time-to-first-working-agent or repeated setup work, and that developers choose the paved road because it is easier, not because a policy forces them to.
