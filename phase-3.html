Phase 03 · months 2–4

RAG and context engineering

Outcome

Design context systems that retrieve the right evidence, respect permissions and can be evaluated independently of the model.

Context is a system

Retrieval-augmented generation is not "put documents in a vector database". Production context systems have ingestion, parsing, chunking, metadata, indexing, ranking, authorization, freshness, deduplication and evaluation concerns. The question is not "did the model answer?" but "did the system retrieve the evidence required to answer correctly?"

Retrieval fundamentals

Learn embeddings, similarity search, HNSW, lexical search such as BM25, hybrid search, metadata filtering, query rewriting, reranking and chunking strategies. Postgres with pgvector and full-text search keeps the architecture understandable; compare a dedicated engine only when data justifies it.

Beyond RAG: context engineering for agents

Agents also retrieve by acting: coding agents mostly search with grep, file reads and tool calls rather than embeddings, and often do better for it. Learn when agentic search beats a vector index, and the other context levers – compaction and summarisation of long sessions, subagents that keep their own context isolated, persistent memory files, and deliberately small tool outputs. This is what "context engine" means in the Staff posting.

Ingestion, freshness and authorization

Build ingestion as an idempotent pipeline: stable source identity, content hash, version and access-control metadata, incremental re-indexing, deletions handled. Treat access control as part of retrieval, not a post-filter: if Alice cannot read a document, it never enters her candidate context. Learn tenant isolation, row-level security and identity propagation.

Build: two context systems

Your product: build a labelled set of real queries with expected source documents, measure recall at k, and separate retrieval failures from generation failures. Forge: index a repository, its docs, ADRs, issues and pull requests; answer "why does service X use this database?" with citations; compare vector, hybrid and agentic search on the same questions.

Exit milestone

You can debug a wrong answer by separating retrieval failure from generation failure, show retrieval metrics, explain chunking decisions, prove permission filtering and update the index incrementally. You can argue when an agent should search with tools rather than a vector index.
