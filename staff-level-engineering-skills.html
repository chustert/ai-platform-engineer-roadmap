Beyond the phases

Staff-level engineering skills

Technical depth is necessary but not sufficient for Staff. The transition is from solving hard problems yourself to creating technical leverage across an organisation. You still ship – mostly by directing agents – but your highest-value outputs are standards, architecture, mentoring, incident leadership and systems that make other engineers (and their agents) faster.

1. Architecture under ambiguity

Make reversible decisions quickly and irreversible ones carefully. Write down assumptions, constraints and alternatives. Prefer architectures that preserve options when requirements are unclear, and revisit decisions with real data rather than defending them. Agents make it cheap to prototype two options before choosing – use that.

2. RFCs and ADRs

Short RFCs for cross-team changes, ADRs for important implementation choices: problem, constraints, options, recommendation, trade-offs, rollout and success measures. Agents can draft; the decision and the reasoning must be yours.

3. Influence without authority

Pair with teams, listen to their pain and earn adoption through usefulness. When proposing a standard, make migration easier than staying put. Collect counterexamples; offer a documented escape hatch. Rolling out coding agents across a team is the clearest current example of this skill – and one you can practise now.

4. Incident leadership

Reduce uncertainty: establish impact, assign investigation threads, keep a timeline, decide mitigations, communicate clearly. Afterwards, fix systems rather than blame people, and turn failures into tests, alerts, runbooks or architecture changes.

5. Mentoring and technical multiplication

Teach through design review, pairing and reusable examples. Run workshops on agent security, tracing, eval design and effective agent use. Review other teams' agent architectures. Raise the organisation's average rather than becoming the only person who can operate the platform.

Artifacts to practise

  • RFC: Standard agent observability
  • RFC: Rolling out coding agents to an engineering organisation (permissions, telemetry, cost governance, enablement)
  • RFC: Internal MCP/tool security model
  • ADR: Orchestration framework versus custom state machine
  • ADR: Model-provider abstraction strategy
  • SLO: PR review agent
  • Threat model: agent tool execution and coding-agent permissions
  • Postmortem: runaway token-spend incident
  • Runbook: model provider degradation
  • Guide: how to add an eval before changing a prompt
